# ADR-0008 — Separate programme authority from operational observations

Status: proposed; acceptance requires the formal configured reviews and H-tier
Linux/Windows/terminal gates for the remediation head. No live execution authority.

## Context

At main `51bec2b8937f725e9e1c74136249a1d9c7d4851a`, active goal and B04 held
652,129 bytes of mixed-era state. The adapter enabled staged Editor while current
instructions disabled it. Dependency-ready records included research-only and
explicitly blocked work. Product merges and lifecycle projections had separate
ancestry requirements, obscured by universal pre-freeze prose. Deleted paths were
absent from risk classification. Reuse and terminal policy hashes used different
path sets and did not bind the durable harness. Normal packaged collection did
not run the offline harness tests. Most CI source jobs checked the synthetic PR
merge rather than the exact head claimed by terminal evidence.

## Decision

Keep canonical semantics and existing mutation/generation machinery. Add a small
read-only derived execution view over canonical readiness, lifecycle, phase and
priority, with structural downstream metrics and historical work locators.
Previously merged products are verification candidates, never automatic completion.
Related/required-input/activation edges do not silently become blocking edges.
Ownership-safe parallel admission additionally needs a complete root-reconciled
local writer census, exact Git/PR/programme identity and disjoint source/tests/
runtime resources. Local observations confer no mutation, merge or distributed
locking authority. Root alone admits workers and serialises integration.

Archive former operational chronology byte-for-byte. Keep AGENTS and active entry
points durable and small; do not commit moving main/head/current-issue assertions.
Read AGY state from the adapter, routing from existing durable config/roles, and
live installation from explicit local evidence. Preserve the twelve V2 roles and
real named review independence. No AGY direct authoritative editing, partial
candidate filtering or independent programme ownership is introduced.

Include deletions/rename origins in classifier input, and share exact protected
identity paths between reuse and terminal summaries, including tests and harness.
Collect the offline harness in protected pytest. Verify CI checks out the exact
reported head and that it incorporates the freshly fetched exact base; no stale
branch-only substitute for integration testing. Preserve all existing H/C gates.

## Narrow supersession and limits

This supersedes the content-independent E exemption for active goal/B04 in prior
delivery prose: those paths now contain durable policy, not chronology. It also
replaces the universal demand for ancestor-bound post-product completion inside an
unmerged product PR. The existing ancestry guard, transition order, append-only
GitHub authority, zero-action readback and ADR-0006 remain unchanged. ADR-0007's
serial package authority, cadence, report-only pilot and process-only GitHub
protection remain intact. No historical ADR is rewritten.

Manifest membership alone does not mean rendered output. DELIVERY_WORKFLOW is a
protected hand-authored pass-through source; canonical control is an edit source
also included in atomic output. Registry/readiness/status views remain generated.
Generation baseline denotes imported evidence, not current main. No new monolithic
plan, duplicated evidence approval database or general GitHub mutation framework.

## Consequences and validation

Fresh roots read two small entries and one derived report, then a complete selected
issue card. Existing expensive evidence has locators and explicit invalidation
reasons. Old sidecars invalidated by the stronger identity binding are preserved,
not regenerated as passing. Missing local ownership/runtime/Skill or formal review
proof stays explicit and fails closed.

Regression coverage includes deletion/rename risk, dirty/committed diff union,
canonical AGY ownership rejection before CLI lookup, graph cycles/lifecycle
exclusions/deterministic ranking, stale/overlapping lanes, reviewer capacity,
CI checkout/base identities and offline harness collection. No product financial
calculation or canonical issue requirement/status is changed by this decision.
